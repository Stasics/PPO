# 01. Vision & Scope — интерактивная онлайн-доска «Бордлайн»

**Этап:** 1.0 · **Курс:** Проектирование ПО, 3 курс
**Автор:** Голованёва Анастасия
**Спикер:** Голованёва Анастасия

---

## 1. Идея продукта

«Бордлайн» — интерактивная онлайн-доска для командной работы в реальном времени.
Аналог Trello и Miro, но с фокусом на:

- совместное редактирование без конфликтов (сервер — источник истины);
- гибкие правила работы (WIP-лимиты, финальные колонки);
- интеграцию с GitHub и Jira;
- прозрачную историю изменений.

**Одно предложение:** доска, где команда видит курсоры друг друга, карточки
перетаскиваются мышью, а сервер гарантирует, что две вкладки не разойдутся.

---

## 2. Контекст проекта

### 2.1. Проблема

Мы сравнили четыре инструмента:

| Инструмент | Сильная сторона | Слабость |
|------------|-----------------|----------|
| Trello | Простота, drag & drop | Слабая работа в реальном времени, нет presence |
| Notion | Гибкость, документы | Доска — не главный режим, правила слабые |
| Miro | Совместная работа, курсоры | Нет структуры «колонка → карточка», нет WIP-лимитов |
| Linear | Скорость, интеграции | Нет свободной доски, жёсткая методология |

**Вывод:** нужна доска, которая соединяет совместную работу в реальном времени
(Miro) со структурой канбан-доски (Trello) и гибкими правилами (WIP-лимиты).

### 2.2. Целевая аудитория

- Продуктовые и проектные команды 3–15 человек
- Студенческие команды
- Команды, которые ведут задачи в GitHub и хотят видеть их на доске

### 2.3. Ключевое архитектурное решение

**Сервер — источник истины, браузер только показывает.**

Почему: если каждый браузер будет решать сам, две вкладки разойдутся —
«побеждает тот, кто дольше держал мышь». Поэтому все изменения проходят
через сервер, а браузер — тонкий клиент.

## 3. Границы системы

### 3.1. В объёме (7 областей)

1. **Структура:** пространства → доски → колонки → карточки
2. **Drag & drop** карточек с WIP-лимитами
3. **Presence:** кто онлайн, где курсор
4. **Комментарии, @упоминания, уведомления**
5. **Лента активности и история изменений** карточки
6. **Гостевые ссылки** — чтение без регистрации
7. **Интеграция** с GitHub и Jira

### 3.2. Вне объёма (8 пунктов)

1. Спринты и эпики как отдельные сущности
2. Story points
3. Офлайн-режим
4. Платный тариф
5. Мобильное приложение
6. Видеозвонки
7. AI-ассистент
8. Кастомные поля карточек

### 3.3. Почему границы именно такие

- **Спринты/эпики не моделируем** — не нужны для ценности продукта.
  Это метки или просто не моделируется.
- **Офлайн-режим** — открытый вопрос к заказчику, но в текущий объём не входит.
- **Платный тариф** — открытый вопрос, границы ещё не определены.
- **Мобильное приложение** — веб-версия покрывает сценарии.

> Упражнение «делаем / не делаем» заняло 40 минут групповой работы.
> Результат: 7 областей в объёме, 8 пунктов вне объёма.

## 4. Ключевые решения этапа

| № | Решение | Почему |
|---|---------|--------|
| 1 | Сервер — источник истины, браузер только показывает | Иначе две вкладки разойдутся |
| 2 | Позиция карточки — по версии, текстовые поля — last-write-wins | Порядок карточек смешать нельзя |
| 7 | Модель: пространство → доска → колонка → карточка | Позволяет переиспользовать структуру и права |
| 8 | Спринт и эпик не моделируются | Не нужны для ценности продукта |
