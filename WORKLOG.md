## 1. Идея продукта

«Бордлайн» — интерактивная онлайн-доска для совместной работы в реальном
времени. Аналог Miro, но с фокусом на три вещи:

- **совместная работа без конфликтов** — сервер гарантирует, что две
  вкладки и разные пользователи не разойдутся;
- **присутствие** — видно, кто онлайн и где его курсор;
- **лёгкость** — быстрый холст без перегрузки функциями.

**Одно предложение:** свободный холст, где команда видит курсоры друг
друга, стикеры перетаскиваются мышью, а сервер гарантирует, что у всех
одна правда.

## 2. Контекст проекта

### 2.1. Проблема

Мы сравнили четыре инструмента для совместной работы на холсте:

| Инструмент | Сильная сторона | Слабость |
|------------|-----------------|----------|
| **Miro** | Мощный холст, много шаблонов, зрелая совместная работа | Тяжёлый, дорогой, перегружен функциями |
| **FigJam** | Красивый, быстрый, интеграция с Figma | Заточен под дизайнеров, не для всех команд |
| **Whimsical** | Простой, быстрые диаграммы | Мало возможностей для свободного холста |
| **Excalidraw** | Лёгкий, бесплатный, рукописный стиль | Нет нормальной командной работы как в Miro |

**Вывод:** нужна доска, которая соединяет лёгкость Excalidraw,
совместную работу Miro и интеграцию с инструментами разработки.
Не перегружена функциями, но даёт всё нужное для команды.

### 2.2. Целевая аудитория

- Продуктовые и проектные команды 3–15 человек
- Студенческие команды
- Команды, которые ведут задачи в GitHub и хотят видеть их на холсте

### 2.3. Что видит пользователь

Свободный холст. На нём:

- **стикеры** — основной объект: цветной квадратик с текстом;
- **фигуры** — прямоугольники, круги, стрелки;
- **текст** — свободные надписи;
- **изображения** — картинки и скриншоты;
- **курсоры участников** — кто где находится прямо сейчас.

Всё перетаскивается мышью. Всё синхронизируется в реальном времени.

## 3. Ключевое архитектурное решение

**Сервер — источник истины, браузер только показывает.**

Почему: если каждый браузер будет решать сам, две вкладки разойдутся —
«побеждает тот, кто дольше держал мышь». Поэтому все изменения проходят
через сервер, а браузер — тонкий клиент.

**Как это работает на холсте:**

1. Кто-то перетаскивает стикер → браузер отправляет запрос на сервер.
2. Сервер проверяет правила и сохраняет новую позицию.
3. Сервер рассылает всем участникам: «стикер теперь здесь».
4. У всех — одна правда.

Если два человека одновременно двигают один стикер — сервер обрабатывает
запросы по очереди. Побеждает тот, чей запрос пришёл первым. Второй
получает уведомление, что данные устарели, и обновляет картинку.

## 4. Границы системы

### 4.1. В объёме (7 областей)

1. **Свободный холст** — стикеры, фигуры, текст, изображения
2. **Drag & drop** объектов по холсту
3. **Присутствие:** кто онлайн, где курсор
4. **Комментарии, @упоминания, уведомления**
5. **Лента активности и история изменений** объекта
6. **Гостевые ссылки** — чтение без регистрации
7. **Интеграция** с GitHub и Jira

### 4.2. Вне объёма (8 пунктов)

1. Канбан-режим с колонками и карточками
2. WIP-лимиты
3. Офлайн-режим
4. Платный тариф
5. Мобильное приложение
6. Видеозвонки
7. AI-ассистент
8. Кастомные шаблоны досок

### 4.3. Почему границы именно такие

- **Офлайн-режим** — открытый вопрос к заказчику, в текущий объём не входит.
- **Платный тариф** — открытый вопрос, границы ещё не определены.
- **Мобильное приложение** — веб-версия покрывает сценарии.
- **Видеозвонки** — не наш профиль, для этого есть Zoom и Meet.

> Упражнение «делаем / не делаем» заняло 40 минут групповой работы.
> Результат: 7 областей в объёме, 8 пунктов вне объёма.

## 5. Ключевые решения этапа

| № | Решение | Почему |
|---|---------|--------|
| 1 | Сервер — источник истины, браузер только показывает | Иначе две вкладки разойдутся |
| 2 | Позиция объекта — по версии, текстовые поля — last-write-wins | Позицию смешать нельзя, текст можно перезаписать |
| 3 | Гость по ссылке никогда не меняет холст | Публичная ссылка не должна утекать в редактирование |
| 4 | Падение GitHub не блокирует работу | Внешняя система не должна останавливать команду |
| 5 | Журнал событий только дополняется, ничего не удаляется | Достоверность истории важнее экономии места |
| 6 | Модель: пространство → доска → объект | Простая иерархия для свободного холста |
| 7 | Канбан-режим не моделируется | Мы аналог Miro, а не Trello |
